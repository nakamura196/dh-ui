# dh-ui

デジタルアーカイブ / デジタル・ヒューマニティーズのアプリで共通に使う
**設計トークン**と **UI 部品**。

複数のアプリ（映像目録、書誌データベース、技術ポータル…）で見た目と操作を
そろえるために切り出した。特定のフレームワークに依存しない層から順に使える。

## 3 段階で使える

| 段階 | 使うもの | 対象 |
|---|---|---|
| 1 | `tokens.css` だけ | React でないアプリでも使える。CSS 変数 |
| 2 | ＋ Tailwind v4 の `@theme` | Tailwind を使うアプリ。`bg-surface` などが生える |
| 3 | ＋ React 部品 | React / Next.js のアプリ |

## 使い方

```bash
npm i file:../../dh/dh-ui       # まずはローカル参照で十分
```

```css
/* app/globals.css の先頭で */
@import "@nakamura196/dh-ui/tokens.css";
```

```tsx
import { SiteHeader, SiteFooter, Hero, Container } from "@nakamura196/dh-ui";
```

Next.js では `next.config.ts` に `transpilePackages: ["@nakamura196/dh-ui"]` が要る。

## 設計の指針

実測にもとづく。参考にしたのはジャパンサーチ（jpsearch.go.jp）。

- **ヘッダは 56px の固定バー**。ページによって高さを変えない（遷移のたびに本文が縦に飛ぶのを防ぐ）
- **本文の最大幅は 1 種類**に統一する。画面ごとに変えない
- **本文 16px / 補助 14px**。11〜12px を多用しない（日本語は潰れる）
- **色数を絞る**。背景 3 色 + 前景 2 色 + アクセント 1 色
- **アクセントは WCAG AA（4.5:1）を満たす値だけ**をトークンに入れる
- 一覧は**多カラムグリッド**。幅が広がったら列を増やす（行が伸びるだけにしない）

## 画面の型は 2 つある

同じトークンと部品を使うが、**閲覧の画面と作業の画面はレイアウトの原則が違う**。
混ぜると、どちらも中途半端になる。

### 閲覧（公開）— 縦に流す

読者は上から順に読み、必要なところで止まる。スクロールは自然な動作。

- ページ全体が 1 本のスクロール
- ヘッダは固定（`--dh-header-h`）、フッターは末尾
- 幅は `--dh-container` で統一
- セクションは意味の単位で区切り、余白でリズムを作る

### 作業（管理・編集）— 1 画面で完結させる

作業者は**同じ画面を何百回も往復する**。ページ全体がスクロールすると、
「動画を見る → 記述を直す」のたびに位置を見失い、手が止まる。

- **ページ全体はスクロールさせない**（`h-screen` + `overflow-hidden`）
- スクロールするのは**中の区画だけ**（記述の一覧、タイムラインの帯など）
- 常に見えているべきもの（動画、選択中の対象、保存状態、進捗）は固定領域に置く
- 操作の帯は 1 本にまとめ、縦の消費を最小にする
- キーボードだけで一巡できるようにする（マウスに戻る回数が作業速度を決める）

```tsx
// 作業画面の骨格
<div className="flex h-screen flex-col overflow-hidden">
  <header className="flex-none" />           {/* 固定 */}
  <div className="flex min-h-0 flex-1">
    <section className="flex-none" />        {/* 動画など。固定 */}
    <section className="min-h-0 flex-1 overflow-y-auto" /> {/* ここだけスクロール */}
  </div>
  <footer className="flex-none" />           {/* タイムラインなど。固定 */}
</div>
```

`min-h-0` を忘れると flex の子が縮まず、内側の `overflow-y-auto` が効かない。
作業画面が「なぜかページごとスクロールする」ときは、たいていこれが原因。
